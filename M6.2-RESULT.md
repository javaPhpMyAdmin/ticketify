### 3. `app.json` plugin check — NO plugin entry needed

**RevenueCat (`react-native-purchases@9.15.2`)**: no Expo config plugin exists.
The package ships `RNPurchases.podspec` and `android/build.gradle` only — Expo
auto-linking picks up the native module at build time. The `node_modules/react-native-purchases/`
directory contains no `app.plugin.js`, `expo-module.config.json`, or equivalent
plugin entry. The RevenueCat Expo docs confirm this pattern: install + dev-client
rebuild, no `app.json` edit.

**Victory-native**: TypeScript-only library (no native code, no podspec). No
plugin entry possible or needed.

**Skia**: TypeScript-only on the JS side; native code is auto-linked via Expo's
existing Android/iOS projects. No `app.json` plugin entry.

**Worklets**: Native module; same auto-link path as skia. No plugin entry.

**Conclusion**: the `plugins` array in `app.json` stays unchanged. No additions
for M6.2. The user's `expo prebuild` (or `eas build`) will pick up the new
native modules at build time.

### 4. `babel.config.js` check — NO file needed

**Discovery**: the project has no `babel.config.js` at all. This is intentional
and correct for Expo SDK 54 — `babel-preset-expo@54.0.12` auto-configures the
required Babel plugins when the relevant packages are installed.

Evidence from `node_modules/babel-preset-expo/build/index.js`:

```js
// Automatically add `react-native-reanimated/plugin` when the package is installed.
hasModule('react-native-worklets') &&
  platformOptions.worklets !== false &&
  platformOptions.reanimated !== false
  ? [require('react-native-worklets/plugin')]
  : hasModule('react-native-reanimated') &&
    platformOptions.reanimated !== false && [require('react-native-reanimated/plugin')]
```

`react-native-worklets@0.8.3` is installed → `react-native-worklets/plugin` is
auto-injected. No manual `babel.config.js` is required. The npm docs for
victory-native that ask the user to add `"react-native-reanimated/plugin"` to
`babel.config.js` are aimed at bare React Native projects; on Expo SDK 54 this
is already handled by `babel-preset-expo`.

**Conclusion**: no `babel.config.js` added or needed. The plugin is auto-loaded.

### 5. Dev-client rebuild still required

Unchanged from the M6.1 spike. The native modules (worklets, skia, purchases,
gesture-handler) are linked into the dev client at build time. The user must
rebuild the dev client before any of the new code can run, otherwise the JS
bundle will throw "TurboModule ... not found" or equivalent native-bridge errors.

Steps (user-driven, out of M6.2 scope):

```bash
pnpm expo prebuild --clean        # regenerates android/ and ios/
pnpm expo run:ios                 # or run:android
```
